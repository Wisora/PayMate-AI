# Contributing to PayMate AI – Investor Presentation Binder

Purpose
Define contributor standards, commit conventions, and onboarding workflow.  
Ensures consistency, accessibility, and investor‑ready documentation across the repo.

Contributor Workflow

1. **Fork the Repo** → Create your own branch for changes.
2. **Clone Locally** → Use VS Code aligned workflows.
3. **Branch Naming** → Use `feature/`, `fix/`, or `docs/` prefixes.
   - Example: `feature/compliance-register-update`
4. **Commit Standards** → Follow conventional commits (see below).
5. **Pull Request** → Submit PR with clear description and linked issue.
6. **Review & Sign‑Off** → Governance Lead or Compliance Officer approves.

Commit Message Format

Use **Conventional Commits** for clarity and automation:

- `feat:` → New feature (e.g., `feat: add risk compliance log`)
- `fix:` → Bug fix (e.g., `fix: correct audit variance calculation`)
- `docs:` → Documentation changes (e.g., `docs: update README.md`)
- `style:` → Formatting, style guide updates (no logic changes)
- `refactor:` → Code restructuring without functional change
- `test:` → Adding or updating tests
- `chore:` → Maintenance tasks

Documentation Standards

- All governance and audit docs stored under `/docs/investor-presentations/`.
- Use **Markdown tables** for registers and logs.
- Include **quarterly sign‑off sections** for accountability.
- Maintain accessibility compliance (contrast, alt text, font sizes).
- Cross‑link related registers (e.g., Risk Log → Mitigation Register).

Accessibility Standards

- Minimum font size: 16pt in visuals.
- Alt text required for all images/diagrams.
- High‑contrast color palette (see Board Deck Style Guide).
- Avoid red/green combinations (color‑blind safe).

Review & Approval

- **Governance Lead** → Oversees governance docs.
- **Compliance Officer** → Validates compliance registers.
- **Investor Relations Lead** → Reviews audit evidence.
- **Finance Lead** → Confirms financial governance records.

Contributor Checklist

- [ ] Repo forked and branch created
- [ ] Commit messages follow conventions
- [ ] Documentation aligned with style guide
- [ ] Accessibility standards applied
- [ ] PR submitted with linked issue
- [ ] Quarterly sign‑off section updated
